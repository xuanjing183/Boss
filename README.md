# BOSS 直聘 · 岗位筛选与打招呼助手

一个油猴（Tampermonkey）脚本，**两部分功能**：

1. **岗位筛选**：按城市/薪资/时长/出勤/HR 活跃度/简历关键词匹配自动筛选并收藏岗位（不调用模型 API）
2. **打招呼**：读取收藏的岗位，结合本地简历，让大模型写出个性化打招呼语，半自动/全自动发给 HR

单文件、无构建、无后端。简历、岗位、草稿、API Key 都只存在本机 Tampermonkey 的存储里。

> 当前版本 **v0.7.1**。界面与文档均为中文，目标站点是 BOSS 直聘网页版（zhipin.com）。

```
第一部分【筛选】（不调用模型 API）
  配置城市/口径 → 打开实习列表页 → 开始筛选
    ↓
  硬性条件过滤（时长/薪资/出勤/硬伤）
    ↓
  关键词简历匹配（本地简历 vs 卡片文本）
    ↓
  打开详情面板 → 读取 HR 在线状态 → HR 状态过滤
    ↓
  达到目标收藏数 → 停止
    ↓
第二部分【打招呼】（调用模型 API）
  收藏列表页 → 抓当前页 → 勾选岗位 → 抓 JD
    ↓
  简历 + JD → 大模型 → 打招呼语草稿
    ↓
  半自动：填进输入框，由你按 Enter 发送
  全自动：确认会话身份后填 + 点发送
```

---

## 先读这个：风险与合规

- **批量自动打招呼违反 BOSS 直聘用户协议**，可能触发限流、功能封禁甚至账号封禁。脚本默认是**半自动**，默认**每日上限 20 条、发送间隔 9–22 秒随机**。先用这套保守值小规模验证，别一上来就全自动跑几十条。
- 脚本在发送前会核对「当前会话就是这条岗位」：拿导航记录里的 `jobId`、右侧职位名做证据。对不上就停手；实在拿不到证据就只填不发，留给你确认。这是为了降低发错人的概率，不是绝对保证。
- API Key 会随请求发给你自己配置的大模型服务商；岗位文本和简历也会进入提示词。用你自己的 Key，**不要提交到公开仓库**。
- 本项目仅供学习交流。使用它产生的账号、法律与社交后果由使用者自行承担。

## 安装

**方式 A（推荐）**：浏览器打开仓库里的 [`boss-zhipin-llm-greet.user.js`](./boss-zhipin-llm-greet.user.js)（或 Raw 地址），Tampermonkey 识别 `.user.js` 后会弹出安装页，点「安装」。

**方式 B（手动粘贴）**：

1. Edge / Chrome 应用商店安装 **Tampermonkey**。
2. Edge 额外确认：`edge://extensions` → Tampermonkey「详细信息」→ 打开 **允许用户脚本**。
3. Tampermonkey 点「添加新脚本」，把整份 `.user.js` 粘进去，`Ctrl+S`。

装好后打开任意 BOSS 页面，右下角出现 **「打招呼助手」** 悬浮按钮；`Alt+P` 显示 / 隐藏面板。油猴菜单里还有「打开/显示助手面板」和「重置全部本地数据」。

> 面板标题会显示版本号（如 `v0.7.1`）。**升级必须整份文件替换**：油猴里的「更新」不会拿到你本地改过的版本。标题栏版本没变，就说明还跑着旧脚本。

## 首次使用

### 第一部分：岗位筛选（不需要配置模型 API）

1. **简历**：选一份 PDF 自动抽取，或直接粘贴正文 →「保存文本」。
2. **筛选 tab**：
   - 配置目标城市（每行一个：城市名，城市代码）
   - 设置筛选口径：目标收藏数、最长实习月数、最低日薪、最多出勤天数
   - 勾选 HR 活跃度筛选（在线/刚刚活跃/今日活跃/昨日活跃/3 日内活跃/本周活跃）
   - 点「保存配置」
3. 打开 BOSS 的**实习岗位列表页**，点「开始筛选当前页」
4. 脚本自动筛选：硬性条件 → 关键词简历匹配 → 打开详情面板 → 读取 HR 状态 → HR 状态过滤 → 收藏符合条件的岗位
5. 达到目标收藏数后自动停止

### 第二部分：打招呼（需要配置模型 API）

1. **设置 → 大模型接口**：填 API Base / API Key / Model，点「连通测试」，日志出现模型回执再继续。
2. 打开 BOSS 的**收藏/感兴趣列表页**，把页面滚到底让懒加载出完
3. 回面板 **岗位 → 抓当前页**
4. **勾选要处理的岗位**（新抓到的默认不勾选）
5. 勾上的岗位若还没有 JD，脚本会后台抓回来
6. **队列**：半自动下点「生成」→ 审草稿 → 点「发送」；全自动下按钮叫「生成并发送」

## 筛选功能详解（v0.7.0+）

### 筛选流程

```
1. 抓取岗位列表
   ↓
2. 硬性条件筛选（时长、日薪、出勤、硬伤、简历关键词匹配）
   ↓ 通过
3. 点击岗位 → 打开详情面板 → 提取 HR 在线状态
   ↓
4. HR 状态过滤（勾选的状态才通过）
   ↓ 通过
5. 点击收藏
   ↓
6. 检查是否达到目标收藏数 → 达到则停止
```

### 筛选条件

| 条件 | 说明 |
| --- | --- |
| 目标城市 | 每行一个：城市名，城市代码（如 `北京,101010100`） |
| 目标收藏数 | 达到后自动停止（默认 20） |
| 最长实习（月） | 超过则跳过（默认 3） |
| 最低日薪（中值） | 低于则跳过（默认 200） |
| 最多出勤（天/周） | 超过则跳过（默认 5） |
| HR 活跃度筛选 | 勾选的状态才通过：在线/刚刚活跃/今日活跃/昨日活跃/3 日内活跃/本周活跃 |
| 最大滚动次数 | 列表页最多滚动加载次数（默认 10） |
| 操作间隔（ms） | 每个岗位之间的等待时间，防风控（默认 1500） |

### 按钮状态机

```
初始状态：无切换按钮
  ↓ 点击"开始筛选当前页"
运行中：显示"暂停" + "停止"
  ↓ 点击"暂停"
暂停中：显示"继续" + "停止"（已保存位置标记）
  ↓ 点击"继续"
恢复运行：显示"暂停" + "停止"（从标记处继续）
  ↓ 点击"停止"
停止：按钮消失，筛选结束
```

- **暂停**：暂时停止，保存当前位置，点击"继续"从标记处恢复
- **停止**：直接结束筛选，无后续操作，按钮消失

### HR 状态抓取

脚本会打开每个岗位的详情面板，在**岗位介绍下方、公司信息上方**的 HR 信息条中读取招聘者在线状态。支持识别：在线、刚刚活跃、今日活跃、昨日活跃、3 日内活跃、本周活跃。

## 岗位详情（JD）是怎么拿到的

**脚本不在列表页点任何按钮，而是把卡片标题那个链接放到后台标签里打开。**

```
「抓当前页」收集 a[href*="job_detail"] / a[href*="jobDetail"] / a[href*="/job/"] → 存进 jobs（含 url，默认不勾选）
        ↓ 勾选 = 进队列（连点几颗并成一批）
fetchDetails() 逐个 GM_openInTab(job.url, {active:false})
        ↓ 后台标签认出「我是来抓详情的」（URL 命中 pendingDetails）
scrapeDetail() 取详情页正文容器 → 写进 GM 存储 details[jobId]
        ↓
面板每 2 秒读存储，把 JD 合并回队列；用完自动关闭该标签
```

有 JD 时提示词里给的是详情页正文；薪资、地点等正文没有的字段仍从卡片带上，两份岗位描述不会互相打架。

### 没抓到 JD 就不生成

生成前 `generateOne()` 会先并回存储里的最新 JD，确认 `hasDetail(id)`；**没有就直接抛错，一个模型请求都不发**。

## 发送

### 两种模式

**半自动（默认）**：脚本负责生成草稿并把话**填进聊天输入框**，最后一下由你按 `Enter` 或点站点「发送」。

**全自动**：生成、走到沟通页、填、点发送全部由脚本在后台标签里完成。队列里的单条按钮也叫「生成并发送」。

### 两个发送入口

| 入口 | 怎么走 | 何时使用 |
| --- | --- | --- |
| **列表卡片入口**（默认） | 另开一个列表页标签 → 滚动找这条岗位的卡片 → 悬停 → 点卡片右上角的「继续沟通/立即沟通」→ 一步到沟通页 | 少开一次详情页，通常更快 |
| **岗位详情页入口** | 另开岗位详情页 → 找沟通入口 → 点它 → 到沟通页 | 关掉列表入口时；也是列表入口明确走不通时的自动退路 |

## 大模型接入

任何 OpenAI 兼容的 `/chat/completions` 都能用。脚本用 `GM_xmlhttpRequest` 直连，绕过 CORS，所以需要 `@connect *`。**API Base 不要带 `/chat/completions`**，脚本会自己拼。

| 服务商 | API Base | Model 示例 |
| --- | --- | --- |
| DeepSeek（默认） | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Moonshot / Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 阿里云百炼（通义） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | `ep-xxxxxxxx`（接入点 ID） |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 自建 / 内网网关 | 按网关地址填，通常末尾带 `/v1` | 网关暴露的模型名 |

### 多模型并行

设置页的「大模型接口」里有一个可折叠的 **「多模型并行（点击展开）」**。展开后是若干张卡片，每张卡片和上面的单模型表单格式一致。

批量时脚本按**岗位 id 的哈希取模**把岗位分给各个模型，每个模型拿到自己的子队列，各自并发生成。

## 批量执行：后台生成器、续跑与多标签

### 生成跑在脚本自己的「生成器」标签页

生成招呼语只需要三样东西：存储里的简历、存储里的 JD、一次模型请求，完全不需要 DOM。所以点「开始批量」会：

1. 往存储写一张交接单；
2. 开一个后台标签页跑生成；
3. 面板变成观众，只显示进度。

因此：
- **你切岗位、翻页、关面板都不会打断生成**；
- 面板日志和生成器日志是**两个独立的键**，两边不互相覆盖；
- 生成阶段是 N 条 promise 链 worker，**不依赖定时器**。

## PDF 简历解析

浏览器沙箱读不了磁盘，所以每次都要手动选文件（`.pdf` / `.txt` / `.md`）。PDF 走 pdf.js 3.11.174，默认从 npmmirror（阿里）加载。依次尝试三条路线，单条超时 25 秒自动换下一条：

1. **主线程 fake worker**（最稳，排第一）；
2. **同源 blob worker**：用 `GM_xmlhttpRequest` 取回 worker 源码打成 blob，绕过站点 CSP；
3. **远程 workerSrc**：要求站点放行镜像域名。

三条都不通时，日志会写明试过哪几条，并提示：**把简历另存为 `.txt` 再选一次，或直接粘贴文本点「保存文本」**。

## 常见问题

**筛选时为什么显示"HR 状态未知"？**
脚本需要打开详情面板才能读取 HR 状态。如果详情面板加载慢或选择器不匹配，会显示未知。检查日志中的 `[HR状态]` 输出，确认详情面板是否成功加载。

**筛选达到目标数后为什么不停止？**
v0.7.1 已修复：每次成功收藏后检查是否达到目标数，达到则立即停止。

**暂停后点击继续，为什么从头开始？**
v0.7.1 已修复：暂停时保存当前位置（`currentIndex`），继续时从该位置恢复。确保使用最新版本。

**"暂停"按钮为什么不显示？**
v0.7.1 已修复：开始筛选后立即调用 `renderScout()` 显示按钮，而不是等筛选结束后才显示。

**「抓当前页」后队列是空的？**
正常。新抓到的岗位默认不勾选，勾上才进队列、才自动抓 JD。

**标题栏「详情」一直是 0？**
先确认岗位已勾选。再查日志：有没有「打开 N 个后台标签抓详情」。一直 0/N 通常是详情页被登录墙挡住、没加载完。

**批量太慢？**
慢在等模型回话。把并发生成数调到 3–8，或配置多个不同模型并行。

**日志出现「模型限流/异常 429，X 秒后重试」？**
把并发生成数调回 1–2。退避重试已带随机抖动。
