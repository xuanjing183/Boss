# BOSS 直聘 · 岗位筛选与打招呼助手

一个油猴（Tampermonkey）脚本，**两部分功能**：

1. **岗位筛选**：按薪资/时长/出勤/HR 活跃度/硬伤关键词/简历关键词匹配自动筛选并收藏岗位（不调用模型 API）
2. **打招呼**：读取收藏的岗位，结合本地简历，让大模型写出个性化打招呼语，半自动/全自动发给 HR

单文件、无构建、无后端。简历、岗位、草稿、API Key 都只存在本机 Tampermonkey 的存储里。

> 当前版本 **v0.8.9**。界面与文档均为中文，目标站点是 BOSS 直聘网页版（zhipin.com）。

```
第一部分【筛选】（不调用模型 API）
  配置口径 → 打开实习列表页 → 开始筛选
    ↓
  第一阶段：卡片文本初筛（时长/薪资/出勤）
    ↓ 通过
  第二阶段：打开详情面板
    ↓
  HR 活跃度检查 → 硬伤关键词检查 → 关键词加权打分
    ↓ 全部通过
  收藏岗位
    ↓
  达到目标收藏数 → 停止

第二部分【打招呼】（调用模型 API 或操作网页版 LLM）
  收藏列表页 → 抓当前页 → 勾选岗位 → 抓 JD
    ↓
  简历 + JD → 大模型 → 打招呼语草稿
    ↓
  半自动：填进输入框，由你按 Enter 发送
  全自动：确认会话身份后填 + 点发送
```

> **多城市筛选**：手动打开多个城市的招聘页面，每个标签页独立运行筛选，互不干扰。

## 先读这个：风险与合规

- **批量自动打招呼违反 BOSS 直聘用户协议**，可能触发限流、功能封禁甚至账号封禁。脚本默认是**半自动**，默认**每日上限 20 条、发送间隔 9–22 秒随机**。先用这套保守值小规模验证，别一上来就全自动跑几十条。
- 脚本在发送前会核对「当前会话就是这条岗位」：拿导航记录里的 `jobId`、右侧职位名做证据。对不上就停手；实在拿不到证据就只填不发，留给你确认。这是为了降低发错人的概率，不是绝对保证。
- API Key 会随请求发给你自己配置的大模型服务商；岗位文本和简历也会进入提示词。用你自己的 Key，**不要提交到公开仓库**。
- 本项目仅供学习交流。使用它产生的账号、法律与社交后果由使用者自行承担。

## 安装

**方式 A（推荐）**：浏览器打开仓库里的 [`boss-zhipin-llm-greet.user.js`](./boss-zhipin-llm-greet.user.js)（或 Raw 地址），Tampermonkey 识别 `.user.js` 后会弹出安装页，点「安装」。

**方式 B（手动粘贴）**：

1. Edge / Chrome 应用商店安装 **Tampermonkey**。
2. Edge 额外确认：`edge://extensions` → Tampermonkey「详细信息」→ 打开 **允许用户脚本**。
3. Tampermonkey 点「添加新脚本」，把整份 `.user.js` 粘进去，`Ctrl+S`。

装好后打开任意 BOSS 页面，右下角出现 **「打招呼助手」** 悬浮按钮；`Alt+P` 显示 / 隐藏面板。油猴菜单里还有「打开/显示助手面板」和「重置全部本地数据」。

> 面板标题会显示版本号（如 `v0.8.9`）。**升级必须整份文件替换**：油猴里的「更新」不会拿到你本地改过的版本。标题栏版本没变，就说明还跑着旧脚本。

## 首次使用

### 第一部分：岗位筛选（不需要配置模型 API）

1. **简历**：选一份 PDF 自动抽取，或直接粘贴正文 →「保存文本」。
2. **筛选 tab**：
   - 设置筛选口径：目标收藏数、最长实习月数、最低日薪、最多出勤天数
   - 勾选 HR 活跃度筛选（在线/刚刚活跃/今日活跃/昨日活跃/3 日内活跃/本周活跃）
   - 配置硬伤关键词（命中任一直接跳过，默认折叠）
   - 配置关键词加分（加权打分，总分≥阈值才收藏，默认折叠）
   - 点「保存配置」
3. 打开 BOSS 的**实习岗位列表页**，点「开始筛选当前页」
4. 脚本自动筛选：
   - **第一阶段**（卡片文本）：时长 ≤ 最长月数、日薪中值 ≥ 最低日薪、出勤 ≤ 最多天数
   - **第二阶段**（详情面板）：HR 活跃度检查 → 硬伤关键词检查 → 关键词加权打分
   - 全部通过 → 收藏岗位
5. 达到目标收藏数后自动停止

> **多城市筛选**：手动打开多个城市的招聘页面，每个标签页独立运行筛选，互不干扰。

### 第二部分：打招呼（需要配置模型 API 或网页版 LLM）

#### 方式一：API 模式（推荐）

1. **设置 → 大模型接口**：填 API Base / API Key / Model，点「连通测试」，日志出现模型回执再继续。
2. 打开 BOSS 的**收藏/感兴趣列表页**，把页面滚到底让懒加载出完
3. 回面板 **岗位 → 抓当前页**
4. **勾选要处理的岗位**（新抓到的默认不勾选）
5. 勾上的岗位若还没有 JD，脚本会后台抓回来
6. **队列**：半自动下点「生成」→ 审草稿 → 点「发送」；全自动下按钮叫「生成并发送」

#### 方式二：网页版 LLM 模式（v0.8.0+）

适用于没有 API Key 或想用网页版 LLM（如 ChatGPT）的场景。脚本会操作你已登录的网页版 LLM 标签页。

1. **设置 → 生成方式**：选择「网页版 LLM」
2. **网页地址**：填 LLM 网址（建议填项目页/新对话页，如 `https://chatgpt.com/`，别填 `/c/` 具体会话）
3. **并行网页数**：设置同时打开的 LLM 标签数（默认 3，建议 2-5）
4. 打开 BOSS 的**收藏/感兴趣列表页**，把页面滚到底
5. 回面板 **岗位 → 抓当前页 → 勾选岗位**
6. **队列**：点「开始批量」，脚本会自动打开多个 LLM 标签页并行生成

> **工作原理**：脚本在后台打开 LLM 网页标签 → 填入提示词 → 等待回复 → 提取结果 → 自动关闭标签页。每个标签页只处理一条岗位，完成后自动关闭以节省内存。

## 筛选功能详解（v0.7.0+）

### 两阶段筛选流程

```
第一阶段：卡片文本初筛（不打开详情面板）
  1. 抓取岗位列表
     ↓
  2. 时长检查：实习时长 ≤ 最长月数
     ↓ 通过
  3. 日薪检查：日薪中值 ≥ 最低日薪
     ↓ 通过
  4. 出勤检查：每周出勤 ≤ 最多天数
     ↓ 通过

第二阶段：详情面板检查（打开详情面板后）
  5. 点击岗位 → 打开详情面板 → 提取完整 JD 文本
     ↓
  6. HR 活跃度检查：状态在勾选范围内才通过
     ↓ 通过
  7. 硬伤关键词检查：命中任一硬伤词 → 直接跳过，不收藏
     ↓ 通过
  8. 关键词加权打分：总分 < 阈值 → 跳过，不收藏
     ↓ 通过
  9. 执行收藏
     ↓
  10. 检查是否达到目标收藏数 → 达到则停止
```

### 筛选条件

| 条件 | 说明 |
| --- | --- |
| 目标收藏数 | 达到后自动停止（默认 20） |
| 最长实习（月） | 超过则跳过（默认 3） |
| 最低日薪（中值） | 低于则跳过（默认 200） |
| 最多出勤（天/周） | 超过则跳过（默认 5） |
| HR 活跃度筛选 | 勾选的状态才通过：在线/刚刚活跃/今日活跃/昨日活跃/3 日内活跃/本周活跃 |
| 硬伤关键词 | 命中任一直接跳过（默认折叠，可开关） |
| 关键词加分 | 加权打分，总分≥阈值才收藏（默认折叠，可开关） |
| 最大滚动次数 | 列表页最多滚动加载次数（默认 10） |
| 操作间隔（ms） | 每个岗位之间的等待时间，防风控（默认 1500） |

### 硬伤关键词

**位置**：筛选 tab 内，默认折叠，点击标题栏展开。

**作用**：命中任一硬伤词 → 直接跳过该岗位，不收藏。

**配置**：
- 开关：勾选「启用硬伤关键词检查」才生效
- 添加/删除：每行一个硬伤词，支持自定义
- 默认值：`2027 届`、`2026 届`、`27 届`、`26 届`、`985`、`211`、`硕士`、`博士`、`C++`、`算法研究`、`纯前端`、`硬件`、`嵌入式`、`测试`

### 关键词加分

**位置**：筛选 tab 内，默认折叠，点击标题栏展开。

**作用**：对岗位 JD 进行关键词加权打分，总分 ≥ 阈值才收藏。

**配置**：
- 开关：勾选「启用关键词打分」才生效
- 收藏阈值：总分达到此值才收藏（0 = 跳过此关卡，默认 5）
- 技能项：每项包含名称、别名（逗号分隔）、权重（1-10，默认 1）
- 打分规则：名称或任一别名命中 → 获得该项权重分，每组最多加一次

**示例**：
```
技能项：Spring Cloud
别名：Spring Cloud Alibaba, Nacos, OpenFeign, Sentinel, Seata, Gateway
权重：1

→ JD 中只要出现 "Spring Cloud" 或任一别名 → 得 1 分
→ 同一组内多次命中不再重复加分
```

### 按钮状态机

```
初始状态：无切换按钮
  ↓ 点击"开始筛选当前页"
运行中：显示"暂停" + "停止"
  ↓ 点击"暂停"
暂停中：显示"继续" + "停止"（已保存位置标记）
  ↓ 点击"继续"
恢复运行：显示"暂停" + "停止"（从标记处继续）
  ↓ 点击"停止"
停止：按钮消失，筛选结束
```

- **暂停**：暂时停止，保存当前位置，点击"继续"从标记处恢复
- **停止**：直接结束筛选，无后续操作，按钮消失

### HR 状态抓取

脚本会打开每个岗位的详情面板，在**岗位介绍下方、公司信息上方**的 HR 信息条中读取招聘者在线状态。支持识别：在线、刚刚活跃、今日活跃、昨日活跃、3 日内活跃、本周活跃。

## 岗位详情（JD）是怎么拿到的

**脚本不在列表页点任何按钮，而是把卡片标题那个链接放到后台标签里打开。**

```
「抓当前页」收集 a[href*="job_detail"] / a[href*="jobDetail"] / a[href*="/job/"] → 存进 jobs（含 url，默认不勾选）
        ↓ 勾选 = 进队列（连点几颗并成一批）
fetchDetails() 逐个 GM_openInTab(job.url, {active:false})
        ↓ 后台标签认出「我是来抓详情的」（URL 命中 pendingDetails）
scrapeDetail() 取详情页正文容器 → 写进 GM 存储 details[jobId]
        ↓
面板每 2 秒读存储，把 JD 合并回队列；用完自动关闭该标签
```

有 JD 时提示词里给的是详情页正文（v0.8.2 起只保留「职位描述 → 任职要求」段落，去掉招聘者/公司信息等噪声）；薪资、地点等正文没有的字段仍从卡片带上，两份岗位描述不会互相打架。

### 没抓到 JD 就不生成

生成前 `generateOne()` 会先并回存储里的最新 JD，确认 `hasDetail(id)`；**没有就直接抛错，一个模型请求都不发**。

## 发送

### 两种模式

**半自动（默认）**：脚本负责生成草稿并把话**填进聊天输入框**，最后一下由你按 `Enter` 或点站点「发送」。

**全自动**：生成、走到沟通页、填、点发送全部由脚本在后台标签里完成。队列里的单条按钮也叫「生成并发送」。

### 两个发送入口

| 入口 | 怎么走 | 何时使用 |
| --- | --- | --- |
| **列表卡片入口**（默认） | 另开一个列表页标签 → 滚动找这条岗位的卡片 → 悬停 → 点卡片右上角的「继续沟通/立即沟通」→ 一步到沟通页 | 少开一次详情页，通常更快 |
| **岗位详情页入口** | 另开岗位详情页 → 找沟通入口 → 点它 → 到沟通页 | 关掉列表入口时；也是列表入口明确走不通时的自动退路 |

### 自动关闭标签页（v0.9.0）

所有脚本打开的标签页在完成任务后会自动关闭（受 `autoCloseDetail` 配置控制，默认开启）：

- **详情抓取标签**：抓取完成后关闭
- **发送标签**：发送成功或接力跳转后关闭
- **网页 LLM 执行器标签**：生成完成后关闭

用户自己打开的页面（推荐页、收藏列表页）不会被关闭。

## 大模型接入

### API 模式

任何 OpenAI 兼容的 `/chat/completions` 都能用。脚本用 `GM_xmlhttpRequest` 直连，绕过 CORS，所以需要 `@connect *`。**API Base 不要带 `/chat/completions`**，脚本会自己拼。

| 服务商 | API Base | Model 示例 |
| --- | --- | --- |
| DeepSeek（默认） | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Moonshot / Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 阿里云百炼（通义） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | `ep-xxxxxxxx`（接入点 ID） |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 自建 / 内网网关 | 按网关地址填，通常末尾带 `/v1` | 网关暴露的模型名 |

### 网页版 LLM 模式（v0.8.0+）

脚本可以操作你已登录的网页版 LLM（如 ChatGPT），无需 API Key。

**工作原理**：
1. 脚本在后台打开 LLM 网页标签
2. 自动填入系统提示词、简历、岗位信息
3. 等待 LLM 回复
4. 提取回复内容作为打招呼语
5. 自动关闭标签页

**配置项**：
- `genMode`: 设为 `'web'` 启用网页模式
- `webUrl`: LLM 网址（建议填项目页，如 `https://chatgpt.com/`）
- `webConcurrency`: 并行标签数（默认 3，建议 2-5）
- `webParts`: 拼接哪些元素（system/user/resume/job）
- `webTimeoutMs`: 单条超时（默认 180000ms）

### 多模型并行

设置页的「大模型接口」里有一个可折叠的 **「多模型并行（点击展开）」**。展开后是若干张卡片，每张卡片和上面的单模型表单格式一致。

批量时脚本按**岗位 id 的哈希取模**把岗位分给各个模型，每个模型拿到自己的子队列，各自并发生成。

## 批量执行：后台生成器、续跑与多标签

### 生成跑在脚本自己的「生成器」标签页（v0.8.0+）

生成招呼语只需要三样东西：存储里的简历、存储里的 JD、一次模型请求，完全不需要 DOM。所以点「开始批量」会：

1. 往存储写一张交接单；
2. 开一个后台标签页跑生成；
3. 面板变成观众，只显示进度。

因此：
- **你切岗位、翻页、关面板都不会打断生成**；
- 面板日志和生成器日志是**两个独立的键**，两边不互相覆盖；
- 生成阶段是 N 条 promise 链 worker，**不依赖定时器**。

### 网页模式的并行批量（v0.9.0+）

网页版 LLM 模式支持多标签并行生成：

```
点「开始批量」
   ↓
按 webConcurrency 配置打开多个 LLM 标签页（默认 3 个）
   ↓
每个标签页只处理一条岗位（通过 URL hash 中的 rid 精确分配）
   ↓
各标签页独立运行，互不干扰
   ↓
完成后自动关闭标签页
```

**关键设计**：
- 每个 worker 有独立的状态 key（`webState_w0`, `webState_w1`, ...），避免状态冲突
- 请求认领使用 `rid` 精确匹配，防止多标签抢同一条
- 调度方（面板）负责分配和关闭，执行方（标签页）只负责处理

## PDF 简历解析

浏览器沙箱读不了磁盘，所以每次都要手动选文件（`.pdf` / `.txt` / `.md`）。PDF 走 pdf.js 3.11.174，默认从 npmmirror（阿里）加载。v0.8.0 起改为按需加载（不再用 `@require`），避免全站匹配时每个页面都解析 377KB。依次尝试三条路线，单条超时 25 秒自动换下一条：

1. **主线程 fake worker**（最稳，排第一）；
2. **同源 blob worker**：用 `GM_xmlhttpRequest` 取回 worker 源码打成 blob，绕过站点 CSP；
3. **远程 workerSrc**：要求站点放行镜像域名。

三条都不通时，日志会写明试过哪几条，并提示：**把简历另存为 `.txt` 再选一次，或直接粘贴文本点「保存文本」**。

## 常见问题

**筛选时为什么显示"HR 状态未知"？**
脚本需要打开详情面板才能读取 HR 状态。如果详情面板加载慢或选择器不匹配，会显示未知。检查日志中的 `[HR状态]` 输出，确认详情面板是否成功加载。

**筛选达到目标数后为什么不停止？**
v0.7.1 已修复：每次成功收藏后检查是否达到目标数，达到则立即停止。

**暂停后点击继续，为什么从头开始？**
v0.7.1 已修复：暂停时保存当前位置（`currentIndex`），继续时从该位置恢复。确保使用最新版本。

**"暂停"按钮为什么不显示？**
v0.7.1 已修复：开始筛选后立即调用 `renderScout()` 显示按钮，而不是等筛选结束后才显示。

**「抓当前页」后队列是空的？**
正常。新抓到的岗位默认不勾选，勾上才进队列、才自动抓 JD。

**标题栏「详情」一直是 0？**
先确认岗位已勾选。再查日志：有没有「打开 N 个后台标签抓详情」。一直 0/N 通常是详情页被登录墙挡住、没加载完。

**批量太慢？**
慢在等模型回话。把并发生成数调到 3–8，或配置多个不同模型并行。网页模式可调大 `webConcurrency`。

**日志出现「模型限流/异常 429，X 秒后重试」？**
把并发生成数调回 1–2。退避重试已带随机抖动。

**网页模式打开多个标签后，有的标签没反应？**
v0.9.0 已修复：每个 worker 有独立状态 key，请求认领使用 `rid` 精确匹配。确保使用最新版本。

**脚本打开的标签页不自动关闭？**
检查 `autoCloseDetail` 配置是否为 `true`（默认开启）。发送失败时标签页会保留，方便查看卡在哪一步。

## 关键选择器

站点改版时优先核对这几处。

| 位置 | 选择器 / 特征 |
| --- | --- |
| 岗位卡片链接 | `a[href*="job_detail"]`、`a[href*="jobDetail"]`、`a[href*="/job/"]`，需可见且文本 2–80 字 |
| 卡片字段 | `.job-name` / `.salary` / `a[href*="company"]` / `.company-location` / `.tag-list` |
| 下一页按钮 | `[class*="next"] button`、`.ui-icon-chevronright`、文本「下一页」 |
| 沟通入口（详情页） | `<div class="btn btn-startchat-wrap">` 内套 `<a class="btn btn-startchat">` |
| 聊天输入框 | `div.chat-input[contenteditable="true"]`。v0.6.0 起**只认聊天容器里的可编辑区**，`<input>` 永远不算 |
| 发送按钮 | `div.btn-v2.btn-sure-v2`，文案精确为「发送」 |

## 数据与隐私

全部数据在本机 Tampermonkey 存储里。

| 存储键 | 内容 |
| --- | --- |
| `cfg` | 打招呼配置，含 **API Key 明文**（仅本机） |
| `scoutCfg` | 筛选配置（城市/口径/HR 状态等） |
| `scoutProgress` | 筛选进度（已收藏/已跳过/运行状态/当前位置） |
| `scoutReport` | 筛选报告（每个岗位的判定结果） |
| `resumeText` | 简历文本 |
| `jobs` / `details` / `drafts` | 岗位列表 / JD 详情 / 草稿与发送记录 |
| `stats` | 今日已发送、已生成计数 |
| `webState_w0` / `webState_w1` / ... | 网页模式各 worker 的状态（v0.9.0+） |

**不要把带 Key 的 `cfg` 上传到任何公开仓库。换电脑前手动备份。**
