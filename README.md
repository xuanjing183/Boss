# BOSS 直聘 · 收藏岗位大模型打招呼助手

一个油猴（Tampermonkey）脚本：**把你收藏的岗位 + 你的简历一起交给大模型，生成个性化的打招呼语，再半自动/自动发送给 HR。**

单文件、无构建、无需后端。所有数据（简历、岗位、草稿、API Key）只存在你本机 Tampermonkey 的存储里。

> 界面与文档均为中文，目标站点是中国求职平台 BOSS 直聘（zhipin.com）网页版。

```
收藏列表 ──抓取──> 岗位队列 ──后台标签抓详情──> JD 全文
                                    │
                       简历(PDF/文本) ┴──> 大模型 ──> 打招呼语草稿
                                                        │
                                    半自动：填进输入框，你按回车
                                    全自动：开沟通页 → 填 → 点发送
```

---

## ⚠️ 先读这个：风险与合规

- **批量自动打招呼违反 BOSS 直聘用户协议**，可能触发限流、功能封禁甚至账号封禁。脚本默认是**半自动**，且默认**每日上限 20 条、发送间隔 9–22 秒随机**，请保持这些保守值先小规模验证。
- 全自动链路里，脚本在**确认「当前会话就是这条岗位」之前不会点发送**：证据对不上就停手，实在拿不到证据就只填不发、留给你确认。这是为了不把话发给错的 HR，不是保证。
- API Key 会经过第三方大模型服务商；岗位与简历文本也会随提示词发出去。用你自己的 Key，别提交到公开仓库。
- 本项目仅供学习交流，作者不对使用它造成的任何账号或法律后果负责。

## 安装

**方式 A（推荐，装了 Tampermonkey 后近乎一键）**：用浏览器打开仓库里的 [`boss-zhipin-llm-greet.user.js`](./boss-zhipin-llm-greet.user.js)（或它的 Raw 地址），Tampermonkey 会识别 `.user.js` 并弹出安装确认页，点「安装」即可。

**方式 B（手动粘贴）**：

1. Edge/Chrome 应用商店安装 **Tampermonkey**。
2. Edge 额外一步（不同版本菜单文案略有差异）：`edge://extensions` → Tampermonkey「详细信息」→ 打开 **允许对用户脚本**；若脚本仍不注入，再到 `edge://settings/content` 里把目标站点的「JavaScript / 用户脚本」权限放开。Chrome 一般开箱即用。
3. 点「添加新脚本」，把 [`boss-zhipin-llm-greet.user.js`](./boss-zhipin-llm-greet.user.js) 的**整份内容**粘进去 → `Ctrl+S`。

**装好后**：打开 BOSS 直聘网页版任意页面，右下角会出现 **「打招呼助手」** 悬浮按钮，`Alt+P` 随时显示/隐藏面板；油猴扩展菜单里也有「打开/显示助手面板」和「重置全部本地数据」两项。

> 面板标题上会打 `v0.4.1` 这样的版本号。**改完脚本忘了整份替换是最常见的坑**，动手前先确认这里的版本和文件里 `@version` 一致。

## 首次使用（照着走一遍）

1. **设置** 标签：填 API Base / Key / Model → 点「连通测试」，日志里出现成功回执再继续。
2. **简历** 标签：选一份简历 PDF 自动抽取，或直接把正文粘进文本框 → 「保存文本」。
3. 去网页版的 **「收藏/感兴趣」列表页**，把页面**滚到底**（懒加载全部出来后），回面板 **岗位** 标签点 **「抓当前页」**（或「自动翻页抓」）。
4. 勾选你要处理的岗位（**选中 = 加入队列**），点 **「抓选中岗位详情」** —— 脚本会开后台标签逐条抓 JD 全文，抓完自动关闭，详情数会显示在标题栏。
5. **队列** 标签：单条点「生成」→ 审一下草稿 → 点「发送」；或点「开始批量」按策略逐条跑。日志标签里能看到每一步发生了什么。

## 两种发送模式

### 半自动（默认，推荐先用它）

脚本只负责生成草稿并**把话填进聊天输入框**，由你审一眼再按 `Enter` 或点站点「发送」。

- 你**当前就站在沟通页**时：当场填好、当场发出。
- 当前页**不是**沟通页时：脚本会另开一个标签页走到这条岗位的沟通页，**只填不发**，队列里标成「已填待确认」。
- 它**绝不会**在你正在看的页面上去点岗位卡片上的「立即沟通」—— 收藏列表每张卡片都有一颗，点错就把 A 岗位的话发给了 B 的 HR，而且一点就整页跳走。

### 全自动

一条完整链路（都是脚本自己开后台标签完成的，你不用切页面）：

```
GM_openInTab(岗位页) → 岗位页找到沟通入口 <a class="btn-startchat" redirect-url="/web/geek/chat?...jobId=...">
   → 点击（整页跳转） → 沟通页 boot() 认领「发送接力」
   → 等输入框出现（最多 20s） → 确认会话身份 → 填 → 点发送（等按钮自己摘掉 disabled）
   → 以「输入框被清空」为唯一成功信号 → 写回执 → 发送方认领 → 成功才关掉标签
```

两个细节值得知道，因为它们决定了你会看到什么日志：

- **点沟通入口是整页跳转**，跳转后原来的 JS 上下文连同 `await` 一起销毁。所以回执由跳转后的沟通页写，接力牌放在 `sessionStorage`（跟标签页走、跨同源导航还在、别的标签看不见）—— 用它区分「脚本刚点进来的一跳」和「你自己随手开的沟通页」。TTL 60 秒，过期作废，绝不留自动发送的地雷。
- **会话身份判定分三档**：
  - `yes`（导航记录里的 `jobId/securityId` 对得上，或右侧 `span.position-name` 与岗位标题归一化后互相包含）→ 填并发送；
  - `unknown`（页面拿不到任何可比对证据）→ **只填不发**，状态「已填待确认」；
  - `no`（证据明确指向另一个岗位）→ **一个字都不填**。

## 大模型接入

任何 OpenAI 兼容的 `/chat/completions` 都能用。脚本用 `GM_xmlhttpRequest` 直连，绕开浏览器 CORS，所以需要 `@connect *`，首次保存后如被问到授权，同意即可。

| 服务商 | API Base | Model 示例 |
| --- | --- | --- |
| DeepSeek（默认） | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Moonshot / Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 阿里云百炼（通义） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | `ep-xxxxxxxx`（接入点 ID） |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 自建/内网网关 | 按你的网关地址填，末尾带 `/v1` | 网关里暴露的模型名 |

> 表里的地址按各家公开文档整理，实际以你控制台给出的为准。**API Base 不要带 `/chat/completions`**，脚本会自己拼。

默认 System 提示词做的事：第一句直接说你是谁、能做什么；从简历里挑 2–3 条与 JD 最匹配的经历/技能，不编造；60–120 字单段落，像真人在聊天框打字，不用 markdown、不加 emoji；不出现薪资期望和「贵公司」。**换简历、改提示词、改模型都会让旧草稿自动标记为「草稿已过期」**（按简历+JD+模型+提示词等做指纹），批量时会重新生成，避免把按旧简历写的话术发给新 HR。

## PDF 简历解析

浏览器沙箱读不了你的磁盘，所以每次都得手动选一次文件（`.pdf` / `.txt` / `.md`）。PDF 走 pdf.js 3.11.174，默认从 npmmirror（阿里）加载 —— 因为 jsdelivr / unpkg 在中国大陆经常超时。脚本会依次尝试三条解析路线，单条超时 25 秒自动换下一条：

1. **主线程 fake worker**（最稳，排第一）；
2. **同源 blob worker** —— 用 `GM_xmlhttpRequest` 把 worker 源码取回来打成 blob，绕过站点 CSP，且不需要 `eval`；
3. **远程 workerSrc** —— 要求站点放行镜像域名，失败得很快。

三条都不通时，日志会告诉你试过哪几条、分别卡在哪，并提示兜底方案：**把简历另存为 `.txt` 再选一次，或直接粘贴文本后点「保存文本」**。

若镜像地址在你的网络下也不通，把文件头 `@require` 和「设置」里的 `pdfWorkerSrc` 一起换成下面任一个：

```
https://cdn.bootcdn.net/ajax/libs/pdf.js/3.11.174/pdf.min.js
https://cdnjs.cloudflare.com/ajax/libs/pdf.js/3.11.174/pdf.min.js
https://cdn.staticfile.net/pdf.js/3.11.174/pdf.min.js
```

## 常见问题

**点了发送，15 秒/60 秒没反应，日志说「后台标签没回执」。**
先确认「自动点击『立即沟通』」是开着的（全自动必开）。生产页面上沟通入口是 `<div class="btn btn-startchat-wrap">` 里套一个 `<a class="btn btn-startchat">`，**事件只绑在里面那个 `<a>` 上**；早期版本按文档顺序点到外面那层 `<div>`，处理器根本不会跑（冒泡只往上）。现在脚本会剔掉「包含另一个候选」的外层节点。

**日志出现「沟通页认不出当前会话是这个岗位」。**
沟通页会把地址栏洗成 `https://www.zhipin.com/web/geek/chat`（query 全没了），而且**整页没有任何 `a[href*="job_detail"]`** —— 「查看职位」是个不带 `href` 的 div。现在脚本改用两档证据：浏览器「导航计时」记录里那一跳的完整 URL（`jobId` / `securityId` 还在），以及页面右侧 `span.position-name` 的职位名。都拿不到时退化成「只填不发」，你去那个标签页看一眼再按 `Enter`。

**岗位标题后面跟着一串地点，像 `Java 后端开发工程师 [ 上海·浦东新区 ]`。**
收藏列表的链接文本就会带这个尾巴，它会同时污染提示词和职位名比对。抓取时会剥掉尾部地点括号并回填到 `city`；圆括号里只有出现 `市/区/·` 之类才当作地点，所以 `（实习）`、`（React）` 不会被误当。已存队列里想清掉脏标题，再点一次「抓当前页」即可（重抓只刷新文本，不会把取消勾选冲回选中）。

**「岗位」页取消了勾选，「队列」页却还留着那条。**
勾选状态就是队列成员资格，现在随抓取落库、切勾选即时生效，未发送草稿一并丢弃。旧版本因为「全选/取消」只改了 DOM 的 `checked`（JS 赋值不触发 `change`）而出现两页状态不一致，已修。

**为什么发送成功的判断只看「输入框清空」？**
早期版本把「页面正文里出现了这段话」也算成功，但输入框里的文字本来就在正文里 —— 于是没发出去也报成功、还标成已发送。现在只认输入框清空，且已发送的行不再给「发送」按钮（重复给同一个 HR 发一遍算骚扰，也容易被风控）。

**站点改版后不管用了怎么自校准？**
按[关键选择器](#关键选择器)在真实页面上（F12）核对，改对应常量即可，抓取逻辑本身不依赖具体接口参数。

**给 Issue 附什么？** 「日志」标签点「复制全部」的完整日志、面板标题上的版本号、你用的是半自动还是全自动、以及哪一步开始出现偏差。**贴日志前请自行打码** `securityId`、`lid` 之类的会话参数，它们等同于凭证。

## 关键选择器

站点改版时优先核对这几处（均在本机已登录的 Edge 上实测过）：

| 位置 | 选择器 / 特征 |
| --- | --- |
| 岗位卡片链接 | `a[href*="job_detail"]`、`a[href*="/job/"]`，需可见且文本 2–80 字 |
| 卡片字段 | `.job-name` / `.salary` / `a[href*="company"]` / `.company-location` / `.tag-list` |
| 下一页按钮 | `[class*="next"] button`、`.ui-icon-chevronright`、文本 `下一页` |
| 沟通入口 | `<a class="btn btn-startchat" redirect-url="/web/geek/chat?id=…&jobId=…&securityId=…">`，`data-isfriend="true"` 时文案是「继续沟通」 |
| 聊天输入框 | `div.chat-input[contenteditable="true"]`（层级：`chat-conversation > message-controls > chat-im.chat-editor > editor-container`；`position:fixed` 元素 `offsetParent` 为 null，可见性判断不能只看 `offsetParent`） |
| 发送按钮 | `button.btn-v2.btn-sure-v2.btn-send`，空输入时的 `disabled` 只是 **class**，填到位后框架自己摘掉 |
| 会话身份 | `performance.getEntriesByType('navigation')[0].name` 里的 `jobId` / `securityId`；右侧 `span.position-name`（必须限定 `rect.left >= innerWidth*0.28`，左侧会话列表里会出现别的岗位名） |
| 需要排除 | 沟通页工具栏上有 3 个 `input[type=file]`（其中图片上传是 0×0 且 `opacity:0`），以及脚本自己面板里的 `<textarea>` |

## 开发

```
boss-zhipin-llm-greet.user.js   唯一的生产文件，装它就行
test/                            回归测试
  build-test.js                  从 .user.js 里切出 SCRAPER-BEGIN/END 之间的抓取代码，注入仿真 DOM
  build-ui.js                    生成 UI / 发送接力的仿真页面（fixture 照真实 DOM 写）
  build-pdf.js                   生成中文 PDF 解析的三条路线页面
  run.js                         用本机 headless Edge/Chrome 渲染并收集断言结果
```

```bash
# 需要较新的 Node.js，以及本机已安装的 Edge 或 Chrome（脚本会自己找 msedge.exe / chrome.exe）
node test/run.js
```

13 个套件、196 条断言，覆盖抓取逻辑、端到端闭环、后台标签接收端、发送接力的 7 种情形（sessionStorage 主路径 / GM 存储兜底 / 标题混进地点 / 只填不发 / 无职位名 / 会话对不上 / 过期牌作废），以及中文 PDF 的三条解析路线。

改选择器逻辑后重新生成测试页：`node test/build-test.js`（抓取）、`node test/build-ui.js`（UI 与接力）、`node test/build-pdf.js`（PDF）。断言结果渲染在 `test/_run_*.html` 里，可以双击打开看。

> **一条踩过的教训**：测试 fixture 必须照真实 DOM 写。曾经有 170 项全绿的回归测试同时伴随着真机失败 —— 因为 fixture 里凭空写了个 `<a href="/job_detail/…">查看职位</a>`，而真实沟通页根本没有 job_detail 链接。现在有一条断言专门钉住「沟通页上确实没有任何 job_detail 链接」。

## 已知限制

- 依赖网页版 DOM；BOSS 直聘灰度改版可能随时让某个选择器失效。
- 未验证：站点反爬（`_security_check`）在真实批量场景下的表现；非好友状态下走完 `friend/add` 之后站点究竟跳到哪儿（实测样本是好友态的「继续沟通」）。
- IE / 移动端浏览器不支持。
- 不会自动回复 HR 的消息，也不会替你面试。它只把第一句话说体面。

## 版本

当前 **v0.4.1**（2026-10-16）。面板标题、启动日志都会打印版本号，报 Issue 时请一并附上。

近期改动（0.4.x）：

- 点沟通入口是**整页跳转**，跳转后原上下文销毁 —— 新增跨页「发送接力」：`sessionStorage` 为主（跟标签页走、别的标签看不见，用来区分「脚本刚点进来的一跳」和「你自己随手开的沟通页」），GM 存储兜底，TTL 60 秒且用完即清。
- 修「点了 15 秒没反应」：沟通入口外面那层 `<div>` 和里面的 `<a>` 文本完全一样，按文档顺序会点到 `div` 上而站点的事件绑在 `<a>`，现在会剔掉「包含另一个候选」的外层节点。
- 会话身份判定不再依赖 `a[href*="job_detail"]`（真实沟通页整页都没有这种链接），改为导航计时记录里的 `jobId/securityId` + 右侧 `span.position-name` 双证据，并新增「拿不到证据就只填不发」的退化档。
- 抓取时剥掉收藏列表标题尾部的地点括号（`xxx [ 上海·浦东新区 ]`），地点回填到 `city`，避免污染提示词和职位名比对。
- 半自动不再要求你自己先打开沟通页：当前页没有输入框时，脚本另开标签页走到该岗位的沟通页**只填不发**，队列标「已填待确认」；但在你正在看的页面上永远不碰岗位卡片的「立即沟通」。
